# J02 · 全文写作精读

论文：A New PUF Based Lock and Key Solution for Secure In-field Testing of Cryptographic Chips。

本轮已完整读取实际 PDF p1–12 的文本，并逐页查看全部 12 张原页渲染图；p10–11 为参考文献，p11–12 另含作者简介。正文、引文格式和简介文体分开理解。标识 P01B08 指 `extracted/J02.json` 内实际页及从 1 起计的文本块，不把跨栏切块误算成自然段。

执行 Supervisor-Skills 的论证链、引言功能及忠于原义的语言分析。这里研究的是写法，不声称独立完成电路、安全、概率或实验复现。

## 1. 摘要逐句分析

|p1 B08 中的次序|承担的工作|语言选择|
|---|---|---|
|1|给扫描攻击问题|主语是威胁对象，先说明为什么需要保护|
|2|交代现有 lock-and-key 的正常使用流程|require…before…把要求和执行门槛放在一起|
|3|从单芯片风险转到共享密钥引发的多芯片风险|However 后的 that share a common test key 是限定问题范围的关键关系从句|
|4|提出逐芯片唯一性作为回应|We address this open problem 回指上一句；不是泛称提升安全|
|5|用一次调用与固化回应重复读取的不稳定性|only once 同时承担时间约束和设计动机|
|6|说明设计方何时、怎样获得所需信息|can only…at the time…without…把权限、时机和禁止的通道都交代|
|7|说明生产测试保持，且发生在锁定前|before the passed chips are locked 是零测试时间代价的边界|
|8|总结安全分析与成本|is analyzed to be 区分本文分析与硅片实测；negligibly small 仍须结合 p9 的芯片规模理解|

这篇比 J01 的优势列表更强调生命周期。值得学习的不是一律用八句摘要，而是让读者知道“谁在什么阶段能做什么”。

## 2. p1–3：把问题收窄到共同硬件与独有密钥的矛盾

|原文位置|逐段内容与任务|可迁移的写法|
|---|---|---|
|p1 B05–07|标题明确 PUF、lock/key、现场测试与密码芯片；第一作者及合著信息单列|对象、使用阶段和机制共同限定标题，而非只用 secure system|
|p1 B12|从不可避免制造故障说到检测成本，再说 scan 怎样提高控制/观察能力|背景不是直接吹捧 PUF，而是先建立不能放弃测试的实际需要|
|p1 B13–14|同一访问能力可用于攻击；熔丝和 BIST 虽阻断攻击却限制现场维修与诊断|these countermeasures 回收前述方案，either…or…分清两种损失|
|p1 B15|介绍现代 lock/key 的正常效果，再指出 privileged user 泄漏、共享密钥、掩模成本及 NVM 风险|逐步追问保护方案新增的管理问题，缺口不是“已有保护都无效”|
|p1 B16–p2 B05|从物理波动解释 PUF，再用 Ideally/In practice 区分理想重复性和实际位翻转|先建立技术作用，再交代它并非无代价；reconciliation 的面积/延迟与具体 PUF 结构绑定|
|p2 B06|KR 复用为 PUF，响应只生成一次、写入 OTP；不同芯片共享硬件但密钥独有|even though 明确看似冲突的两项性质怎样共存；生产与现场测试分阶段叙述|
|p2 B07|章节导航把 scheme overview、controller、analysis 分开|“控制器”不是总览的同义重复，而是将权限落到阶段操作的独立任务|
|p2 B09–10|先说 boundary-scan/STW 正常行为，再说存储或共享钥匙的风险|If/As/Because 按条件、原因推进，保留 privileged/unprivileged 的区别|
|p2 B11|从寄存器对应假设讲到顺序混淆，再说明 signature 只需足够状态的反例|先复述原设计赖以成立的假设，再指出反例；知识条件是比较轴|
|p2 B12–p3 B05|历史状态、静态/动态混淆和 LFSR 种子的风险逐步展开|后续方案确实改进了哪些点也被承认；不是为了引出本文把所有方案一起判负|
|p3 B06|加密、离线 LFSR、测试激励嵌入等路线最终回到共享 key 的责任问题|None of…addresses 把分类结果综合为共同缺口；non-repudiation 是管理层的额外评价维度|
|p3 B08|先并列“共享 key 好攻击”和“每芯片 key 难量产测”，再提出 universal lock|On the other hand 连接真正相互牵制的需求；To address this dilemma 把新架构写成矛盾的解法|
|p3 B09–10、图1|把 designer、foundry、user 按真实操作顺序安排在图与正文中|生产先不锁→设计方激活/固化→授权用户现场测试；对象、权限和时间不靠读者猜|
|p3 B11|总览结束后列控制器、锁、mask generator、OTP、KR/hash 的构件|模块清单出现于流程总览之后，读者先知道目的再看到零件|
|p3 B37–p4 B05|用两项目标引入 obfuscation：无效 key 输出错误、设计方能在激活时导出 key|两条不是重复安全口号，而是对手阻断与合法方可用性两项要求|

## 3. p4–6：按正常行为、扰动行为和可辨识条件解释方法

|原文位置|逐段理解|语言与组织|
|---|---|---|
|p4 B46–47、图2|先明确 full/partial/parallel 适用，再用近似等长子链简化解释|For simplicity/without loss of generality 是作者声明的简化；使用时仍需判断是否真的可推广|
|p4 B47、图3(a)|逐门说明两个 XOR、两个 AND、相邻单元与 mask 位|每个控制信号有明确作用，不只说“加入混淆电路”|
|p4 B105–107–p5 B05–07、图3(b–e)|先给未修改扫描链的时序与下标，再分 00/11/01/10；由局部扰动说明后续传播|正常基线先于差异；When/Unlike 分别承担分支和比较；不能把 XOR 的两种影响混写|
|p5 B08|将单对混淆单元推广到多对，通过局部片段的前后边界改记号|扩展不是只说 similarly，而是说明替换哪些边界和索引|
|p5 B09|从各情形可区分性推导两个响应位条件|all four cases can be discriminated if…保留 if；读者知道判据为什么存在|
|p5 B10|设计方根据已知输出选择位置，再用正常/混淆响应差异恢复 mask|This way 把前一段判据转成构造步骤；only the designer 依赖其位置及响应知识|
|p5 B11|将 chip uniqueness 连接到 PUF response 与 mask，而不直接混称 test key|同一唯一性目标由 response→mask→key 多步实现，术语不能来回替换|
|p5 B12|给“合理唯一性”的一般选择，再说明 KR 复用和可替代 SCAN-PUF|In principle/Alternatively 标记可以替代的构件，不把当前实例说成唯一实现|
|p5 B13|承认硅 PUF 位翻转，再用一次生成固化绕开重现性需求|学习“改变使用协议使某项难题不再必要”，而不是“PUF 已被改造成完美可靠”|
|p5 B14–15–p6 B05|给 Λ、R、Z、Zu、Hk 与 F 的作用，分别写锁前、锁后、解锁；进一步用 keyed hash 避免完全依赖 OTP 隐蔽|To avoid fully relying…公开说明安全依赖并补机制；With the knowledge of…逐项列出合法方需要的信息|

这一部分最重要的写作技巧，是每次定义都紧接一个尚未解决的操作问题：有了唯一响应仍须安全取回；有了 OTP 仍不应完全依赖隐蔽；有了锁还须让生产测试可执行。它不是用堆叠技术名形成复杂感。

## 6. p10–12：参考文献与作者简介

p10 B11–12 与 p11 B05 的 33 条参考文献全部读取其文献类型、编号与格式；没有据此声称每篇外部原文已核实。正文 p1 将 PUF 标注为 [5]，而本地参考文献 [5] 的题名是 common test data；这种内部对应需要另行核对，不能复制为分身的引用范式。

正文中 one-time programmable、one-time pad 的写法并不统一。本项目记录的是“只生成一次并固化到 OTP 的使用方式”；未来稿件应先按器件与协议的实际含义统一名称，不能因一个缩写相同而混用术语。

p10 致谢写 funding 与 corresponding author；p11–12 简介按学历、经历、当前领域/职责组织。这些是独立文体，不进入正文论证与措辞偏好，也不将稿件中的历史任职当作现在事实。

## 7. 精读后新增、且会影响写作分身的规则

1. **用生命周期解释安全条件。** 不是所有秘密从制造之初就存在，也不是合法方在所有阶段都能恢复信息。写 key、mask、nonce 时标明生成、保存、使用与失效的阶段。
2. **把成本写成“增量＋分母＋规模＋复用条件”。** 本文 3.80% 与 31.66% 的同增量例子，是避免“低开销”泛化的直接证据。
3. **区分解决一个性质与改变使用方式。** 一次生成绕开重复响应需求，并不等于提高了 PUF 的物理重复可靠性。
4. **对手模型需要具体知识和时机。** 有未锁芯片、知道电路功能、知道混淆位置、取得一次编程机会，是不同条件。
5. **对前人更公平，贡献才更清楚。** 有些方案面积确实更低；本文以责任可追溯及每芯片 key 区分，不声称所有指标最好。

## 8. 两篇连读产生的区别

J01 的主线是把输出变换成不可直接恢复的表示，J02 的主线是让同一保护硬件在不同生命周期承担生产与授权测试。两篇都写“安全、低开销、保持测试性”，但支撑这些词的机制、条件和测试对象不同。

因此，崔老师口吻不能简化成反复使用 secure、low overhead、hence：应先确定当前研究的矛盾属于哪一种，再采用相应的因果链、分阶段叙述和限定方式。
