# J14 全文精读

*Static and Dynamic Obfuscations of Scan Data Against Scan-Based Side-Channel Attacks*，14页，Cui第一作者合著。2026-10-21全部叙述页块实际读完；原JSON B零基；P10/P11/P12实际视觉核对并读缺失表I–III，其余未标visual true。

## 全页段覆盖

- P1B1–B8、P2B1–B2：摘要不是直接“新防御全面好”，而是static补旧lock→新TMOSA暴露在PI直输下失效→dynamic防御，沿自我修正论证。引言从制造缺陷/scan高可测到crypto中间值可窥双刃剑，再评mode reset/MKR/subchain reorder/advancedDFT不是天然安全。static只对受保护boundary plaintext输入安全，PI直输为新攻击条件；test-key加载N拍相对大test set而小，不是零开销。
- P2B3–B5、P3B1–B4：review mode-switch攻击与test-only的reset差异；signature不需scan order/精确capture，known crypto function/架构仍为前提；non-boundary PI也可在capture输入，扩大威胁。图2/3展示每cracking cycle时机，不能把test-only说成完全没有capture正常逻辑计算。
- P3B5–B6、P4B1–B3：从plaintext/key/algorithm三因素推countermeasure分类；dubious input难识别且延迟、MKR不能online/roundkey不可测、SDSFF依赖fault-unknown状态使原test适配失效、mode reset被test-only绕、TSC/ROS只换顺序不够、VIm输出全0暴露wrong key且可绕输出gate。TSC扩展LFSR恰使部分子链不可达的附带收益也承认，随后给“若敏感位仍全可达则不安全”caveat。
- P4B4–B5、P5B1–B3：SOSD选择N/L SFF的tc由SR Q/Q′+OR与系统TC控制；correct key使tc0/wrong使从CUT取数据切断shift。2bit counter识别TC连续高≥2为normal、N拍加载key；key硬编码在Q/Q′连线而非memory，不须comparator；obfuscation无明显输出全0反馈，迟延攻击判定。无mem不等于无物理知识攻击，作者在此按non-invasive边界。
- P5B4–B6、P6B1–B3：static三个性质：mismatch为blocking cell、其后的all matched则输出它、靠SO最后blocking对应PBB。三attack假设：plaintext能正确入模块、可收scan、已知crypto/架构但不知scan细节；PBB作为逐位解除的弱点，论证明确指出自己方案适用前提。
- P6B4–B10：AES128 roundkeys、16×8bit section、simulator sensitized签名对真实all signatures配比；未知scan order需全匹配，false positive随plaintext量可降；TMOSA同divide-conquer但加blocking处理，不把传统signature原理算为本文发明。
- P7B1–B4：完整六步found_key/matched_responses/B/U初始化、猜section、翻test-key保/还原/未解决、遍历/重访PBB；需更多匹配判断纠正，scan order已知O(L)未知O(L²)；321平均/369worst plaintext及T成本为基于特定AES实现的分析量，不是统一硬件实测攻击时间。文末N64/128倍率与前述二次公式需原作者复核，本轮不按数字复制推演。
- P8B1–B2：作者明确static弱点是independent/static test-key bit控制；若boundary scan亦有mismatch阻止正确plaintext，attack Assumption1不成立，所以仍安全；不是static在所有场景彻底失败。
- P8B3–B6、P9B1–B5：DOSD保骨架加循环MUX/wideOR/fallingedge latch：correct key freezeSR，wrong key mismatch锁存1持续循环使PBB动；即使循环一度匹配也不能停，latch是关键。controller两counter、TC两拍识别normal、一拍capture不触发重load，Fig9时序逐步读；P/T分别选SFF位置与Q/Q′，SHA-1为2017示例，不能作当前安全推荐。
- P9B5、P10B1–B5：N3 P{4,2,7}/T101，wrong100→010→001循环；表I15拍从scan-in到capture/scan-out逐行读，d未知从CUT加入，原1010001变101d6d9d7d10，response与下vector继续改变；可选计数wrong attempts限速不是当前电路必然已有功能。
- P10B6–B9、P11B1：correct test key才令原DFT/ATPG vectors透明，原CUT fault coverage保持；**额外controller/SR/gates不经scan测**，作者建议BIST或放弃。wideOR/mismatch stuck0会无声降DOSD为SOSD但功能可正常，不能把“no impact testability”写成所有protection fault都被检测或不影响security。
- P11B2–B6：security按随机guess、PBB移动无法逐一固定、避免全0/全1shift-invariant key、OTP接口也可泄讨论；“all known/unconditional”限此时此攻击/假设集合，不是普遍数学安全证明或未来攻击免疫。
- P11B7–B8、P12B1–B4、P13B1：pipelined/iterative AES KS，scan排除cipher-key registers，N64/128；表II SOSD增388/716 gates、DOSD531/998，pipelined0.18–0.47% vs iterative1.52–3.91%。同固定增量不同分母，不只摘below0.5。表III用pipelined scan212280门归一化前作excerpt增量，mode-reset仅原文约10%；security/testability/test time因无统一metric作qualitative，area不是最小但多指标平衡。
- P13B2–B6、P14B1–B4：结论完整回static→TMOSA条件→dynamic，结尾“at least one salient figure”不同于所有指标都胜。参考[1]–[38]按scan性能背景、mode/test-only/signature、countermeasures、AES implementations、other sidechannels与OTP报道读完；作者简介已读，不作现在职位依据。

## 本轮重要限定与机制链

Technique采用“防御—攻击—修补”的论文轴。边界不是事后附注而是新机制来源：允许PI直输→static留下PBB→signature逐位纠正→让PBB循环且锁存mismatch。要学习作者愿意精确展示自己初始方案被攻破的论证透明度，不能把SOSD/DOSD混为一个抽象“更安全”。

新增需保留：scan reorder不等data obfuscation；TMOSA三假设；SOSD安全依赖boundary输入被保护；dynamic latch防偶然循环匹配；testability只原CUT/正确key且保护逻辑不scan；mismatch stuck0会安全降级；same Δgates两AES比例差；N key load仅一次入口固定代价；comparison denominator统一、其他指标qualitative。全文的典型攻击分析不等独立技术正确性复现。

## 原句语言规律

“There is a caveat though: if ...”把对旧法局部认可和失效条件一起说；“To analyze any potential vulnerability of the scheme proposed ...”先立自身可攻击性质；“Nevertheless ... still safe provided that ...”避免过度否定；“except that ... also fed ... latched ...”指出增强版真正关键差别；“Faults ... are, however, not testable”直接暴露测试范围；“acceptably low, though not the minimum”用多指标而非选指标夸张。

可迁移：从失效场景推方法、性质/attack假设/算法互相对齐、控制信号时序详述、原CUT/安全附加逻辑测试范围分开、增量gate数与百分比并报。不可复制：攻击公式/成本/2^-N、unconditional或all-known安全、SHA-1示例、0.5%忽略小设计、fault coverage全系统保证。

未解决：源TMOSA时间倍数与公式的一致性本轮不独立重算，不作为复用数字；all-known安全为2017作者范围主张。全部指定文本和缺表已读。
